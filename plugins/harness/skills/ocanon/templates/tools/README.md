# 개발·검증 도구 색인 — {{PROJECT}}

> 상태: 작성 중 · 최종 갱신일: {{DATE}}
> 역할: 개발·검증에 다시 쓰는 도구(코드·데이터 생성 스크립트, 값 없는 빌드·배포 래퍼, 증거 수집 스크립트, 정적 검사기)의 단일 색인이다.
> 진입: `plan/index.json` 의 `assets.tools_root` 가 이 파일을 가리킨다. 시험 스크립트는 `test/` 에 둔다.

## 원칙
- 필요한 것만 만든다. 남기기 전에 보존 판정을 1회 한다: K4(비중복) ∧ K5(안전·크기) ∧ (K1 재실행 ∨ K2 재생성 비용 ∨ K3 근거성).
- 색인의 "재사용 이유" 칸에 K 번호와 한 줄 이유를 적는다. 빈 칸은 감사 경고 대상이다.
- 재사용 코드 조각은 별도 스니펫 파일로 두지 않고 코드 자체나 공용 모듈에 둔다.
- 판 사본(`_v1`·`_v2`·`_old`·`_bak`·`_copy`)을 만들지 않는다. 기존 도구를 고친다.

## 도구 색인
| 경로 | 용도 | 재사용 이유(K) | 실행 명령 | 마지막 사용 | 상태 |
|---|---|---|---|---|---|
| (예시) `tools/gen_fixture.py` | 시험 픽스처 생성 | K2 수작업 생성 비용 큼 | `python3 -B tools/gen_fixture.py --out <경로>` | {{DATE}} | 사용 |

상태 값은 `사용`·`대체됨→<새 경로>`·`보관(archive/…)` 중 하나다. "대체됨" 행은 다음 정리 때 `archive/` 로 옮긴다(이름·내용 불변). 180일 넘게 쓰지 않았고 대체 도구가 있으면 정리 후보다.

## 안전 규칙
- 서버 주소·포트·계정·토큰 같은 값을 박아 넣지 않는다. 환경변수나 INFRA 문서 참조로만 받는다. 값이 박힌 배포 스크립트는 두지 않는다.
- 1회성 변환기·탐침은 남기지 않는다.
- 도구 실행 결과물은 `tools/` 에 쓰지 않는다. 생성물(`__pycache__`·`*.pyc`·빌드 결과)도 두지 않는다.
