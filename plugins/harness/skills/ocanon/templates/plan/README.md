> 상태: 운영 중 · 최종 갱신일: {{DATE}}
> 이 폴더는 {{PROJECT}} 의 요구·설계·계획·결정을 담는 살아 있는 정본이다. 진입점은 `index.json` 이다.

## 핵심 원칙

1. **plan 은 살아 있는 정본이다.**
   - 작업을 시작할 때 `index.json` 을 먼저 읽고, 거기서 가리키는 관련 문서를 읽는다.
   - 작업이 끝나면 확정된 결정은 ADR(`90_결정관리/02_결정기록_ADR.md`)과 `index.json` 에 남긴다.
   - 바뀐 내용은 해당 문서를 직접 고친다. 판 사본(`_v2`·`_old`·`복사본` 등)을 만들지 않는다.
   - 수치·표처럼 생성되는 내용은 손으로 고치지 않고 `_build/` 스크립트로 다시 만든다.
   - 구현이 plan 과 다른 결정을 요구하면 plan 을 먼저 고친 뒤 구현한다(문서 먼저, 코드 나중).
2. **문서 한 개는 300줄을 넘기지 않는다.**
   - 넘으면 `NN_제목_부록/a1_*.md` 로 나누고 본문에는 부록 색인표만 남긴다.
   - 문서 머리에 "상태·최종 갱신일"을 적는다.
3. **확인되지 않은 내용과 민감한 값은 구분해서 다룬다.**
   - 추정이나 미검증 내용은 문장 앞에 "추정"·"미검증"으로 표시한다.
   - 외부 정보는 출처 URL 을 함께 적는다.
   - 자격증명·서버 주소·포트·계정 같은 값은 적지 않는다. 필요하면 `INFRA.md` 의 해당 절을 참조로만 건다.

## 표준 문서 목록과 템플릿

표준 문서의 전체 목록·최소 목차·갱신 주체는 ocanon 스킬의 `references/CATALOG.md` 를 참조한다.
문서별 템플릿은 같은 스킬의 `references/DOC_TEMPLATES_A.md`(분석·설계)와 `references/DOC_TEMPLATES_B.md`(계획·시험·이행)에 있다.

## 표기 규칙

- 파일명은 `NN_제목.md` 로 짓고, 부록은 `NN_제목_부록/a1_*.md` 로 둔다.
- 문서 머리 두 줄에 상태(작성 중·운영 중·보관)와 최종 갱신일을 적는다.
- ID 는 REQ-NN(요구), FN-NN(기능), SCR-NN(화면), TC-NN(시험), ADR-NNN(결정), D-NN(결정대기), TODO-NN(과제) 형식을 쓴다.
- 확인되지 않은 내용은 "추정"·"미검증"으로 표시하고, 외부 정보에는 출처 URL 을 단다.
