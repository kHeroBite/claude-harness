# 문서 템플릿 B — 계획·시험·이행·결정 (개발범위·WBS·일정표·시험계획·시험케이스·시험결과요약·구축배포·ADR·결정대기·TODO)

> 역할: 계획·시험·이행·결정 단계 주문형 문서의 머리 정보와 최소 목차를 정한다. 카탈로그 전체는 `CATALOG.md` 를 본다.
> 사용법: 해당 절의 `~~~markdown` 블록을 복사해 권장 위치에 만들고, `{{PROJECT}}`·`{{DATE}}` 와 `<…>` 를 채운다.
> 공통: 머리에 상태·최종 갱신일, 300줄 초과 시 `_부록/`, 값(주소·포트·계정)은 INFRA.md 참조만 적는다.

## 2. WBS (wbs)

| 항목 | 값 |
|---|---|
| 카탈로그 키 | `wbs` |
| 권장 위치 | `plan/02_범위_일정/02_WBS.md` (+ `02_WBS.csv` 선택) |
| 생성 시점 | 주문형 — 작업이 여러 사이클에 걸칠 때 |
| 갱신 주체 | oplan(작업 추가), odone_docs(이번 사이클 WBS-ID 상태·진척%) |
| 최소 목차 | 작업 분해표 · 진척 요약 |

csv 열 정의: `WBS-ID,상위,작업,REQ-ID,FN-ID,담당,상태,산출물,진척%,완료일`
- 담당은 역할(oplan·odev·otest·사람)로 적는다. 개인 연락처는 적지 않는다.
- 진척%는 산출물이 실제로 있는 만큼만 올린다. 근거 없는 수치는 쓰지 않는다.

~~~markdown
# {{PROJECT}} WBS

> 상태: 초안 · 최종 갱신일: {{DATE}}

## 1. 작업 분해
| WBS-ID | 작업 | REQ/FN | 담당 | 상태(대기·진행·완료·보류) | 산출물(경로) | 진척% | 완료일 |
|---|---|---|---|---|---|---|---|
| WBS-1 | <단계 작업> | REQ-01 | — | 진행 | — | 0 | — |
| WBS-1.1 | <세부 작업> | FN-01 | odev | 대기 | <경로> | 0 | — |

## 2. 진척 요약
- 완료 <n> / 전체 <m> (<p>%) — {{DATE}} 기준
~~~

서버 주소·포트·계정·명령 인자 값은 쓰지 않는다. 실제 값과 명령은 INFRA.md 가 정본이며 이 문서는 구조만 담는다.

~~~markdown
# {{PROJECT}} 구축·배포

> 상태: 초안 · 최종 갱신일: {{DATE}} · 값·명령: INFRA.md `<절 이름>` 참조

## 1. 환경 구성 (개발·시험·운영 환경의 역할과 차이 — 값 없이)
## 2. 배포 전략 (방식·순서·승인 지점)
## 3. 롤백 (판정 기준·되돌리는 단위)
## 4. 배포 후 점검 (헬스체크 항목 — 명령은 INFRA.md)
~~~

## 8. 결정기록 ADR (decisions)

| 항목 | 값 |
|---|---|
| 카탈로그 키 | `decisions` |
| 권장 위치 | `plan/90_결정관리/02_결정기록_ADR.md` |
| 생성 시점 | init(product·tool) 또는 첫 결정 때 |
| 갱신 주체 | odone_docs |
| 최소 목차 | ADR-NNN 항목(일자·결정·근거·대안·영향·상태) |

결정이 바뀌면 기존 ADR 를 고치지 않는다. 새 ADR 를 쓰고 옛 ADR 상태를 `대체됨→ADR-NNN` 으로 바꾼다.

~~~markdown
## ADR-NNN <제목>
- 일자: {{DATE}} · 상태: 확정 | 대체됨→ADR-NNN
- 결정: <한 문장>
- 근거: <실측·요구·제약>
- 대안: <검토한 안과 기각 사유>
- 영향: <바뀌는 문서·코드·REQ-ID>
~~~
