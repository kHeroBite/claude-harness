# ASSET_RULES — 영역별 자산 규칙과 선별 원칙

> ocanon SKILL.md 의 상세 참조다. 무엇을 어느 영역에 남기고, 무엇을 남기지 않으며, 언제 치우는지 정한다.
> 원칙은 하나다. 다음에 다시 쓰일 근거가 있는 것만 남기고, 쓸모없는 파일은 만들지도 남기지도 않는다.

## 1. 영역 정의

| 영역 | 담는 것 | 커밋 | 배제 | 색인·재사용 방법 | 쓰는 단계 / 읽는 단계 |
|---|---|---|---|---|---|
| `plan/` | 요구·설계·계획·결정·시험계획/결과 요약(카탈로그), `_build/` 재생성 스크립트, 다시 모으기 비싼 조사 원자료(`NN_*/_원자료/`) | 예 | 자격증명·서버 주소·포트·계정(INFRA.md 참조로만), 회차 로그·스크린샷 | `index.json` `documents`(카탈로그 키) → 문서. 수치는 `python3 -B plan/_build/<x>.py` 로 재생성 | oplan(분석·설계·계획), otest(시험계획·결과요약), odone_docs(결정·진척·색인) / 모든 사이클 시작 시 oplan |
| test_root (기본 `test/`) | 재실행 가능한 시험 스크립트(measure·judge·record), 자동화 시나리오(UI·adb·브라우저), 고정 시험 자료·픽스처, 작은 기대값·스냅샷, 결과 전 고정한 판정 규칙(`rules_*.md`), 회귀 가치 있는 재현 스크립트(`repro/`) | 예 | 결과 데이터(→ logs·archive), 실계정·토큰·실서버 주소(환경변수·INFRA 참조로만), 1회성 탐침 | `<test_root>/README.md` 색인표. 판정 규칙은 회차와 무관한 것만 | otest·odebug·odev(중간 실기 확인) / otest·oplan(시험 범위 산정) |
| tools_root (기본 `tools/`) | 코드·데이터 생성 스크립트, 값 없는 빌드·배포 래퍼, 증거 수집 스크립트, 정적 검사기 | 예 | 값이 박힌 배포 스크립트, 1회성 변환기 | `<tools_root>/README.md` 색인표 | odev·otest / odev·otest·oplan |
| `.claude/archive/` | 세션 원본 자동 보관(계획서·AC·result·교훈 원본, 판정 규칙·AC 스크립트 원본) | 아니오(전역 ignore) | — | `INDEX.jsonl` Grep | ofinish 승격 / oplan(선택, `## 정본 참조` 의 과거 산출물) |
| 기존 정본 문서 | PROJECT(as-built 구조)·DATABASE(as-built 스키마·ERD)·HISTORY(변경이력)·LESSONS(과정 교훈)·INFRA(값, 커밋 금지)·`docs/`(PRD·가이드) | 기존대로 | — | docs-map | 기존대로 |

문서는 사람이 읽고 고치며 번호로 찾고, 실행물은 경로·import·실행 명령으로 찾는다. 그래서 `plan/` 과 test_root·tools_root 를 섞지 않는다.

### 색인표 열 (test_root·tools_root README 공통)

| 경로 | 용도 | 재사용 이유(K) | 실행 명령 | 마지막 사용 | 상태 |
|---|---|---|---|---|---|

- 재사용 이유 칸에는 아래 K1~K3 중 무엇에 해당하는지 적는다. 이 칸이 비면 감사가 경고한다.
- 상태 값은 `사용 | 대체됨→<경로> | 보관` 이다.

## 2. 단계별 남길 후보

| 단계 | 남길 후보 | 영역 |
|---|---|---|
| 분석 | 요구 원문 누적, 조사 요약+출처, 실측 수치와 그 측정 명령(재실행 경로), 다시 모으기 비싼 원자료 | plan/00·01, 측정 명령은 test_root·tools_root 경로 인용 |
| 설계 | 아키텍처·ERD(to-be)·기능요건·화면기획·API, 다이어그램 원본(mermaid·svg 텍스트, png 는 `_build` 재생성), 인터페이스 정의 | plan/03~07 |
| 계획 | ADR·결정대기·향후과제, WBS·일정표, 개발범위 | plan/02·90 |
| 개발 | 생성 스크립트, 값 없는 빌드·배포 래퍼. 재사용 스니펫은 코드 자체·공용 모듈로 두고 별도 스니펫 파일을 만들지 않는다 | tools_root, plan/_build |
| 시험 | measure·judge·record 스크립트, 시나리오, 픽스처·기대값, 결과 전 고정한 판정 규칙 | test_root |
| 검증 | 회귀 가치 있는 AC 판정 스크립트(최종판 1개), 판정 요약(기준 대비 결과·남은 FAIL) | test_root `judge/` 또는 `ac/`, plan/08 결과서 |
| 디버깅 | 회귀 가치 있는 재현 스크립트 | test_root `repro/` |
| 배포·운영 | 절차의 일반 부분 | plan/09 (값은 INFRA.md) |
| 마무리 | 진척·색인·ADR 반영 | plan/ |

세션 작업 디렉터리에서 실제로 재사용 후보가 되는 것은 대개 다음 셋이다.
- 결과를 보기 전에 고정한 판정·측정 규칙 문서
- 같은 AC 를 여러 판으로 고친 판정 스크립트의 최종판
- 같은 문제를 다시 일으킬 수 있는 재현 스크립트

나머지(진행 상태 파일·회차 로그·1회성 탐침)는 남기지 않는다.

## 3. 보존 판정 (5문항, 남기기 전 1회)

| 문항 | 질문 |
|---|---|
| K1 재실행·재참조 | 다음 사이클에 다시 돌리거나(입력·명령이 적혀 재현 가능) 다시 읽을 근거가 있는가 |
| K2 재생성 비용 | 실측·조사·판정 근거·사람의 결정처럼 다시 만들기 비싼가 |
| K3 근거성 | 결정·요구·합격 기준의 근거인가 |
| K4 비중복 | 같은 내용이 다른 정본(코드·PROJECT·DATABASE·HISTORY·LESSONS·다른 plan 문서)에 없는가 |
| K5 안전·크기 | 자격증명·서버값이 없고 텍스트 위주 1MB 미만인가(이미지·바이너리는 원본 텍스트에서 재생성할 수 없을 때만) |

판정식은 **K4 ∧ K5 ∧ (K1 ∨ K2 ∨ K3)** 이다. 이 식을 만족할 때만 남긴다.

기록 방법은 각 에이전트 result json 에 다음을 적는 것이다.

```json
"reusable_assets": [ { "path": "test/web/judge/rules_layout.md", "area": "test", "reason": "K1 회차 무관 판정 규칙" } ]
```

해당이 없으면 `"reusable_assets": []` 와 `"reusable_assets_note": "해당 없음"` 을 적는다.

## 4. 남기지 않을 것

- 일회성 로그·콘솔 출력
- 중간 산출물(분석 중 임시 표·덤프)
- 재생성 가능한 생성물: `__pycache__`·`*.pyc`·`bin/`·`obj/`·빌드 결과. `_build` 로 다시 만드는 png·xlsx 는 원본이 있으면 커밋 여부를 선택한다
- 중복본·판 사본: `_v1`·`_v2`·`_r2`·`_old`·`_bak`·`_copy`·`복사본`
- 근거 없는 초안
- 세션 진행 상태 파일: state·`*_done`·ack·heartbeat·stop_last·`askq_*`·`*_result.json`
- 스크린샷·원시 결과(→ archive·logs)
- 대용량 바이너리
- 자격증명·서버값이 들어간 파일
- 1회성 탐침 스크립트

## 5. 경량 경로 (매 사이클 문서 생성 의무화 금지)

| tier | 정본 참조 | 문서 생성·갱신 | 자산 보존 |
|---|---|---|---|
| O1 | 없음 | 없음 | 없음 |
| O2 | 계획서 1~2줄(색인+관련) — 게이트 경고만 | 결정이 생겼을 때만 ADR 1건 | 판정 통과 시만 |
| O3 | `## 정본 참조` 필수(차단) | 반영 예정에 적은 문서만 | 판정 통과 시만 |
| O4·O5 | 필수(차단) | 반영 예정 + 활성 시 WBS·일정 진척 | 판정 통과 시만 |

`반영 예정: 해당 없음(사유)` 로 끝나는 사이클이 정상 경로다. 남길 것이 없으면 아무것도 만들지 않는 것이 맞다.

## 6. 폐기·정리 규칙

1. 같은 주제는 새 파일을 만들지 않고 기존 문서를 갱신한다. 판 사본을 만들지 않는다.
2. 결정이 바뀌면 ADR 를 고치지 않는다. 새 ADR 를 쓰고 옛 ADR 상태를 `대체됨→ADR-x` 로 바꾼다.
3. 수명이 끝난 plan 문서는 `plan/98_보관/` 으로 옮기고 `index.json` 의 `archived` 에 올린다. 삭제하지 않는다.
4. test_root·tools_root 도구가 다른 도구로 대체되면 README 색인에서 `대체됨→<경로>` 로 표시하고, 다음 정리 때 `archive/` 하위로 옮긴다. 이름과 내용은 바꾸지 않는다.
5. 180일 넘게 쓰지 않았고 대체 도구가 있으면 정리 후보다.
6. odone_docs 는 감사 경고(판 사본·고아·`대체됨` 미정리)를 보고 정리 항목을 `90_결정관리/03_향후과제_TODO.md` 에 올린다.

## 7. 기계 확인과 한계

`plan_audit.py` 가 확인하는 것은 다음과 같다.
- 색인 누락(고아)과 깨진 참조
- 판 사본 이름 패턴과 생성물(`__pycache__`·`*.pyc`·`bin/`·`obj/`)
- 1MB 초과 파일, 자격증명 패턴, 300줄 초과 md
- `active_docs` 에 선언했지만 없는 문서
- README 색인의 `대체됨` 미정리, 재사용 이유 칸 공란(경고)

게이트가 확인하는 것은 다음과 같다.
- DEV 전이 때 계획서 `## 정본 참조` 절과 이번 사이클의 `index.json` 읽기 기록
- 마무리 때 `반영 예정` 에 적은 문서가 실제로 바뀌었는지(경고)

한계는 다음과 같다.
- "다음에 쓸모가 있는가"라는 가치 판단 자체는 기계로 판정할 수 없다. 기계는 구조 신호(중복 이름·생성물·크기·색인 누락·이유 칸 공란)만 잡는다.
- 이유를 적었는지는 강제하지만 이유가 타당한지는 사람과 리뷰가 판단한다.
- 읽기 기록은 열람만 증명하고 이해는 증명하지 못한다. 셸 `cat` 으로 읽은 것은 기록되지 않는다.
