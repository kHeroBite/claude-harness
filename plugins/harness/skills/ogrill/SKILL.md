# ogrill — 소크라테스식 요구사항 명확화 스킬

> 모호한 큰 작업 요청을 4행 인터뷰 템플릿과 5축 종료 기준으로 좁혀, 코드/계획에 들어가기 전에 요구사항을 명확히 한다.

**출처**: [deep-interview (devbrother2024, MIT)](https://github.com/devbrother2024/skills) 4행 질문 템플릿 + [grill-me (mattpocock, MIT)](https://github.com/mattpocock/skills) 결정트리 컨셉을 융합. 한국어 환경 + o시리즈 파이프라인에 맞춰 재설계됨. 라이선스 상세는 [LICENSE-NOTICE.md](./LICENSE-NOTICE.md) 참조.

## 핵심 원칙

```yaml
모호_즉시_인터뷰:
  - 사용자가 큰 작업을 모호하게 요청하면 코드/계획 들어가기 전에 인터뷰 시작
  - "일단 만들어볼까" 패턴 절대 금지 — 후반 재작업 비용은 인터뷰 비용보다 100배 큼

한_번에_하나씩:
  - 질문 폭격 금지 (3개 이상 질문 동시 제시 X)
  - 가장 큰 불확실성 1개를 한 번에 1개만 — AskUserQuestion 1회 호출 = 질문 1개
  - 사용자 인지부하 최소화가 명확화 속도보다 우선

코드로_답할_수_있는_건_묻지_마:
  - Glob/Grep/Read로 답 가능한 것은 사용자에게 묻지 말고 직접 확인
  - 예: "어떤 파일에 있나요?" → 직접 검색. "기존 패턴은?" → 직접 Read
  - 사용자에게 물을 것 = "의도/우선순위/취향" 등 코드로 알 수 없는 것만

4행_템플릿_고정:
  - 모든 질문은 동일한 4행 형식 (현재 이해 / 막힌 결정 / 추천 답안 / 질문)
  - 일관성 = 사용자가 매번 새 형식을 읽을 필요 없음

5축_종료_기준:
  - 목표 / 범위 / 제약 / 완료 기준 / 열린 질문 5축 모두 채워지면 종료
  - 5축 미충족 상태로 oplan 진입 절대 금지
```

## 적용 대상 (사용/미사용)

### 사용 (✅)

- 모호한 큰 작업: "뭔가 만들어줘", "리팩토링해줘", "개선해줘" + 범위 흐릿
- 결정 트리 분기 다수: "DB는 MySQL/PostgreSQL? 동기/비동기? 인증 방식?" 등
- oplan 진입 전 요구사항 정리 필요 (forced_tier=o4/o5 큰 작업)
- 사용자 첫 요청이 1~2문장이고 결정해야 할 항목이 5개 이상

### 미사용 (❌)

- 이미 구체적: 파일명+함수명+라인까지 명시된 요청
- 단순 오타/설정 변경/테스트 보강
- 즉시 답 가능: 1문장으로 답할 수 있는 질문/계산
- /ox~/o2 규모 (작은 작업은 인터뷰 비용이 작업 비용 초과)

## 5축 종료 기준 (5축 모두 채워지면 인터뷰 종료)

| 축 | 의미 | 검증 질문 |
|----|------|----------|
| **목표 (Goal)** | 무엇을 달성하려는가? | "1줄로 요약 가능한가?" |
| **범위 (Scope)** | 무엇이 포함/제외되는가? | "Out of scope 항목이 명시되었는가?" |
| **제약 (Constraints)** | 기술/시간/호환성 제약은? | "어떤 것을 깨면 안 되는가?" |
| **완료 기준 (Done)** | 어떻게 완료를 알 수 있나? | "체크 가능한가? (예/아니오로 답할 수 있는가?)" |
| **열린 질문 (Open)** | 결정을 미루는 항목? | "후속 단계로 넘기는 결정이 명시되었는가?" |

5축이 모두 채워지면 인터뷰 종료 → 결정사항 + 열린질문을 oplan 입력으로 전달.

## 4행 질문 템플릿 (절대 형식)

모든 인터뷰 회차는 다음 4행 템플릿을 사용한다. 형식 변경 금지.

```
현재 이해: {요청 1문장 요약}
막힌 결정: {가장 큰 불확실성 1개}
추천 답안: {제시 가능 시 — 없으면 '없음'으로 명시}
질문: {한 가지 질문}
```

- **현재 이해**: 사용자 요청을 1문장으로 정확히 paraphrase. 오해 시 사용자가 즉시 정정할 수 있게 함.
- **막힌 결정**: 5축 중 채워지지 않은 가장 큰 1개 항목.
- **추천 답안**: 코드 탐색/도메인 지식으로 추천 가능하면 명시. 없으면 "없음" 표기 (모르는 척하지 마라).
- **질문**: AskUserQuestion options에 매핑되는 1개 질문.

## 실행 절차

```yaml
Step_0_코드_우선_확인:
  목적: 사용자에게 묻기 전에 코드로 답 가능한 항목 제거
  도구: Glob / Grep / Read / mcp__oio__find / mcp__oio__file_read
  예시:
    - "기존 인증 방식?" → grep -r 'auth' .
    - "DB 스키마?" → mcp__mysql__get_schema
    - "기존 패턴?" → 유사 파일 1~2개 read
  금지: 코드로 알 수 있는 것을 사용자에게 질문

Step_1_5축_빈_칸_식별:
  목적: 사용자 요청에서 5축 중 어떤 항목이 비어있는지 분석
  방법: 사용자 첫 메시지 → 5축 표 그리기 → 빈 칸 표시
  산출: 빈 축 목록 (보통 3~4개)

Step_2_가장_큰_불확실성_1개_선정:
  우선순위:
    1. 목표 (없으면 다른 축 의미 없음)
    2. 범위 (있어야 제약/완료기준 정의 가능)
    3. 제약 (기술 결정에 가장 큰 영향)
    4. 완료 기준 (otest 평가 기준)
    5. 열린 질문 (마지막에 정리)
  선정: 우선순위 가장 높은 빈 축 1개

Step_3_AskUserQuestion_1회:
  파라미터:
    - question: 4행 템플릿 본문 전체 (현재이해+막힌결정+추천답안+질문)
    - options: 2~3개 + 자유 입력 자동 허용
    - multiSelect: false (절대)
    - header: 12자 이내 (예: "DB 선택", "범위 확정")
  금지: 1회 호출에 질문 2개 이상 포함

Step_4_답변_누적_5축_갱신:
  방법: 답변 → 해당 축 채움 → 5축 표 업데이트
  추가_도출: 답변에서 새로운 결정 사항 발견 시 함께 기록
  예: "MySQL 사용" 답변 → 제약(MySQL 호환) 자동 추가 가능

Step_5_5축_미충족_시_Step_2_반복:
  반복_횟수: 보통 2~5회 (5축 빈 칸 수에 비례)
  최대_횟수: 7회 — 그 이상은 사용자 피로도 증가 → "지금까지 결정사항으로 진행할까요?" 제안
  중단_조건: 사용자가 "이 정도면 됐어" 표시 시 즉시 종료

Step_6_5축_충족_종료:
  산출:
    1. 결정사항 (5축 모두 채움)
    2. 열린 질문 (후속 결정 항목)
    3. 권장 다음 단계 (oplan/odev/직접답변)
  전달: oplan 호출 시 입력으로 사용
```

## AskUserQuestion 사용 규약

```yaml
호출_제약:
  - 1회 호출당 questions 배열에 1개 question만 (multiSelect: false)
  - options: 2~3개 (4개 이상 시 결정 피로도 증가)
  - "Other" 옵션은 자동 제공됨 → 별도 추가 금지
  - header: 12자 이내, label 5단어 이내

question_파라미터_본문:
  - 4행 템플릿 전체를 question 본문에 포함
  - 줄바꿈은 \n 사용

label_options:
  - 각 옵션은 1~5단어
  - description 1~2문장 — 트레이드오프 명시
  - "(추천)" 표기는 추천 답안에만 1개

예시_파라미터:
  questions:
    - question: |
        현재 이해: 모니터링 대시보드를 추가하고 싶다.
        막힌 결정: 실시간 갱신 주기 (성능 vs UX 트레이드오프).
        추천 답안: 5초 간격 (대부분의 케이스에서 충분).
        질문: 갱신 주기를 얼마로 할까요?
      header: "갱신 주기"
      multiSelect: false
      options:
        - { label: "5초 (추천)", description: "표준 대시보드 패턴, 서버 부하 적음" }
        - { label: "1초",        description: "거의 실시간이지만 서버 부하 증가" }
        - { label: "30초",       description: "리소스 절약, 단 즉각성 떨어짐" }
```

```yaml
  - mattpocock grill-me 식 16~50개 질문 동시 제시 X

  - 추천 답안 모르면 "없음" 표기 (CLAUDE.md "정보 정직성 원칙" 절대 규칙)

5축_미충족_oplan_진입_금지:
  - 5축이 비어있으면 oplan은 추측으로 계획 → odev 재작업 발생
  - 인터뷰 종료 전 oplan 호출 금지
```

## 메인 에이전트 호출 금지 (절대 규칙)

메인 에이전트는 자율 판단으로 Skill('ogrill')를 호출할 수 없다. 물리 차단이 적용된다.

```yaml
호출_주체:
  허용:
    - oplan 팀에이전트 (oplan/oplan_normal/oplan_deep/oplan_simple/oplan_consult/oplan_debate): Phase A 진입 전 5축 결손 판정 후 직접 호출
    - 사용자 명시 /ogrill 슬래시 직접 호출: UserPromptSubmit.sh가 ogrill_slash_flag 마커 생성 → hook 통과
  금지:
    - 메인 에이전트 자율 판단 호출: PreToolUse_Skill_ogrill_main_guard.sh가 block

물리_차단_근거:
  - hooks/PreToolUse_Skill_ogrill_main_guard.sh: PIPELINE_UUID 부재 + ogrill_slash_flag 마커 부재 → block
  - 메인의 5축 결손 판정은 oplan에 위임 — 메인 자율 판단은 작업 흐름 중단 위험
```

## 선행 호출 매트릭스 (oplan 팀에이전트 전용 — 단일 출처)

> oplan 팀에이전트(oplan/oplan_normal/oplan_deep/oplan_simple/oplan_consult/oplan_debate)가 Phase A 진입 전 이 매트릭스를 참조하여 ogrill 호출 여부를 판단한다. 메인 에이전트는 이 매트릭스를 사용하지 않는다.

```yaml
판정_기준 (5축 빈 칸 카운트):
  빈_칸_4_이상: 즉시 ogrill 선행 강력 권고 (기본값 "예")
    → AskUserQuestion으로 사용자에게 1회 확인 (기본 선택: ogrill 먼저)
  빈_칸_3:     ogrill 선행 약권고 (사용자 1회 확인)
    → AskUserQuestion으로 사용자에게 1회 확인 (기본 선택: 직진)
  빈_칸_2_이하: 스킵 (본 스킬 직진)

5축_빠른_평가 (각 축은 채워짐/빈칸 이진 판정):
  목표 (Goal):         "무엇을 달성?" — 1문장 요약 가능한가?
  범위 (Scope):        "포함/제외 항목?" — Out of scope 명시되었는가?
  제약 (Constraints):  "어떤 것을 깨면 안 되나?" — 기술/시간/호환성?
  완료기준 (Done):     "어떻게 완료 확인?" — 체크 가능한가?
  열린질문 (Open):     "후속 결정 항목 명시?" — 미룬 결정이 있는가?

예외_스킵_조건 (5축 평가 전 우선 적용):
  - 회귀 수정 (직전 동일 파일 수정 보고 + 같은 영역 재수정)
  - 단일 파일 명시 (파일명+함수명+라인 모두 명시됨)
  - 사용자 명시 "바로 진행" / "ogrill 건너뛰기" / "묻지 말고"
  - 이미 ogrill 5축 결과를 이전 메시지에서 제공한 케이스
  - tier ≤ o2 (소규모 작업은 인터뷰 비용이 작업 비용 초과)

호출_타이밍 (oplan 계열 스킬별):
  oplan*:    Phase A(의도분석) 진입 전
  odebate:   3분석가 spawn 전
  oconsult:  Claude+Codex spawn 전
```
