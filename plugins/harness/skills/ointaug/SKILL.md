# ointaug — 사용자 질의 확장 스킬

> 짧고 모호한 사용자 요청을 **프로젝트 컨텍스트 + 이전 대화 + 기법**을 활용해
> 디테일하고 실행 가능한 질의로 확장한다. **절대 줄이지 않는다.**

## 핵심 원칙

1. **항상 확장** — 원문 질의보다 짧아지면 절대 안 됨
2. **프로젝트 특성 반영** — ko파이프라인/oio MCP/WSL2/스킬 체계 컨텍스트 포함
3. **이전 대화 참조** — session_env/plans/user_prompt.md 이력 활용
4. **원문 보존** — 확장 결과에 원문 의도 반드시 포함
5. **기법 조합** — 의도분석 + 질의확장 + 맥락보강 동시 적용

## 적용 기법

> A/B/C/D 4개 기법 적용. 실행 순서: A(의도분석) → D(타당성 판정) → B(질의확장) → C(맥락보강)

### A. 의도분석 (Intent Analysis)
```yaml
목적: 사용자가 진짜 원하는 것이 무엇인지 파악
질문들:
  - 이 요청의 최종 목표는 무엇인가?
  - 어떤 문제를 해결하려 하는가?
  - 어떤 제약/조건이 내포되어 있는가?
  - 성공 기준은 무엇인가?
출력: "사용자 의도: {1~2줄 요약}"
```

### B. 질의확장 (Query Expansion)
```yaml
목적: 핵심 키워드 주변의 관련 개념/맥락을 추가
기법:
  - 동의어/관련어 추가 (예: "줄여" → "압축/경량화/최적화")
  - 암묵적 제약 명시 (예: "스킬 수정" → "SKILL.md 파일, 실행 신뢰성 유지")
  - 범위 명확화 (예: "hook 수정" → "어떤 hook, 어떤 이벤트, 어떤 조건")
  - 관련 파일/컴포넌트 식별
출력: 확장된 키워드 목록 + 관련 파일 경로
```

### C. 맥락보강 (Context Augmentation)
```yaml
목적: 현재 프로젝트/세션/파이프라인 상태를 질의에 반영
소스:
  - 현재 파이프라인 상태 (IDLE/PLAN/DEV 등)
  - 이전 사용자 프롬프트 이력 (session_env/plans/user_prompt.md)
  - 프로젝트 특성:
      ko파이프라인: o1~o5 tier, oplan/odev/otest/odone/ofinish
      oio MCP: 파일I/O 독점, bash_exec, session_state
      WSL2+NTFS: /mnt/c/ 경로, BOM/CRLF, 권한 이슈
      스킬체계: SKILL.md, invocation, user_callable
      Hook체계: UserPromptSubmit/PreToolUse/PostToolUse, UserPromptSubmit.sh
출력: "현재 컨텍스트: {관련 정보}"
```

### D. 기술 타당성 판정 (Feasibility Check)
```yaml
목적: 요청이 기술적으로 "공식 지원"되는지 사전 판정 — 불가능한 기능에 대한 타협 구현 방지
체크_질문:
  - 이 요청이 공식 문서에서 확실히 지원되는가?
  - "작동 안 할 수 있지만 그래도..." 류 타협이 필요한가?
  - 타협안이 사용자 원래 의도를 실제로 달성하는가?
불합격_시_행동:
  - 구현 수락 금지. 코드 작성 금지.
  - 정직한 거절 + 문서 대안 제시 (예: CLAUDE.md 한 줄 안내)
  - 사용자 명시 승인 없이 진행 금지
출력: "기술 타당성: {가능/불가능/부분가능} — {근거 + 공식 문서 또는 직접 확인 결과}"
```

적용_순서: A(의도분석) → D(타당성 판정) → B(질의확장) → C(맥락보강)
원칙: 불가능한 요청을 확장해봐야 낭비 — 타당성 판정을 의도분석 직후 수행

## Step 0: ointaug_done 마커 생성 (물리 게이트 해제 — 필수 선행)

`PreToolUse_Skill_ointaug_gate.sh`(F-INTAUG-1)가 ointaug 미경유 파이프라인 진입을 물리 차단한다.
확장 질의를 출력하기 **전에** 아래 마커를 먼저 생성한다. 생략하면 후속 `Skill('ok'/'oto'/...)`가 차단된다.

```
mcp__oio__session_state(uuid="${UUID}", key="ointaug_done",
  value="<epoch>\n대상: {파일/컴포넌트}\n조건: {제약}\n성공기준: {완료 판정}\n컨텍스트: {프로젝트 상태}")
```

- 첫 줄: epoch 초 (기록용 — ★2026-09-15 사이클133부터 게이트 TTL 판정은 이 값이 아닌 파일 mtime(시스템 실측)을 사용한다. `date` 실측 없이 추정으로 적어도 게이트 통과에 영향 없음. TTL 600초는 여전히 같은 턴 내 호출만 인정)
- **2~5번째 줄: 확장 질의 4항목 — `PostToolUse_Skill_ointaug_format.sh`(F-INTAUG-2)가 검사한다.**
  누락 시 경고가 stderr 로 나와 같은 턴 안에서 보강을 요구한다.
  ⚠️ **마커에만 적고 화면 출력을 생략하는 것은 규칙 회피다.** hook 은 출력 텍스트에
  접근할 수 없어 그 우회를 물리적으로 막지 못한다 — 마커와 화면이 일치해야 한다.

### ★출력 축소 금지 (2026-09-13 실사고 — F-INTAUG-2 신설 계기)★
메인이 ointaug 를 호출은 하되 **`확장 질의:` 블록을 통째로 생략**하고 의도분석 한 줄만
출력한 사례가 발생했다. 사이클이 길어지며 **점진적으로 축소**됐고, 사용자가
"간소화된 게 의도한 바냐"고 묻기 전까지 아무도 감지하지 못했다.
⇒ 핵심 원칙 1("항상 확장 — 원문보다 짧아지면 절대 안 됨")은 **맥락이 충분히 공유된
상황에서도 해제되지 않는다.** "이미 다 아는 내용이니 짧게"는 스킬 회피 안티패턴이다.
⇒ 간소화가 필요하다고 판단되면 임의로 줄이지 말고 **사용자에게 먼저 제안**하라.
- 경로 이중화 대응: `session_state` 도구를 쓰면 양쪽 base 에 자동 기록된다.
- ⚠️ 이 마커는 "ointaug 를 실제로 실행했다"의 증거다. 미리 만들어 두고 건너뛰는 행위는
  규칙 회피이며 CLAUDE.md 「스킬 회피 안티패턴」 위반이다.

## 권장 분기 판정 (옵션 C — 명확하면 자율실행)

> **옵션 C 정책**: 의도·분기·tier가 모두 명확하면 메인이 AskUserQuestion 없이 즉시 파이프라인 진입.
> 모호하거나 슬래시 오인 가능성이 있으면 기존처럼 1회 확인.

```yaml
자율실행_조건 (C1·C2·C3 모두 충족 시 → AskUserQuestion 없이 즉시 Skill 호출):
  C1. 권장 분기 단일 명확: ok 파이프라인 + tier 명확, 또는 단일 위임 스킬 명확
  C2. 의도 명확: 슬래시명령 오타·해석 충돌 없음. 사용자 문장에서 행위 동사가 명확히 식별됨
      위반_예시: "/oss 재연결 기능 추가해줘" — oss는 스크린샷 스킬, 기능 요청 의도와 충돌 → 차단
  C3. 비파괴적 + 추가 정보 불필요: DB 마이그레이션·대규모 리팩토링·배포 등 위험 작업 제외

자율실행_차단 (X1~X4 중 1개라도 해당 → 1회 확인):
  X1. 의도 모호 / 슬래시명령 오인 가능성 (예: "/oss 기능 추가" → oss=스크린샷 스킬인데 기능 요청)
  X2. tier 경계 불명확 (o3 vs o4 판단 어려울 때 — 500줄 경계, 아키텍처 변경 여부 불확실)
  X3. 사용자 명시 종료·중단 의사
  X4. 파괴적 가능성 (DB 마이그레이션, 대규모 리팩토링, 배포 등 되돌리기 어려운 작업)

자율실행_진입_통지 (비차단 — 진입 전 반드시 1줄 출력):
  형식: "🤖 [자율진입] {슬래시 명령} — {1줄 판단 근거} — 중단: Ctrl+C"
  예시: "🤖 [자율진입] /ok (o3) — 명확한 코드수정 요청, 4개 파일 수정 예상 — 중단: Ctrl+C"
  이유: 자율진입 후 잘못된 파이프라인이 실행되기 전에 사용자가 즉시 인지·중단 가능

판정_기준 (위에서 아래로 순차 평가):
  단순질문 (직접 답변):
    조건: 1문장 답변 가능, 코드 변경 없음, 정보 확인만
    예: "이 변수명 뭐야?", "Git push 됐어?", "파일 몇 줄?"
    권장: "(직접 답변 가능)"

  ohaiku (빠른 위임):
    조건: 단순 탐색/요약/grep/계산, 메인 컨텍스트 절약 필요
    예: "이 폴더 파일 목록 줘", "이 함수 한 줄 요약해줘"
    권장: "/ohaiku — 단순 탐색/요약은 Haiku가 빠름"

  osonnet (일반 위임):
    조건: 일반 질문/분석/설명, 코드 수정 없음, 1~2개 파일 분석
    예: "이 코드 어떻게 동작해?", "이 에러 원인이 뭐야?"
    권장: "/osonnet — 일반 분석/질문은 Sonnet 위임 권장"

  odebug (디버깅):
    조건: 버그/에러/오류/비정상 동작 보고
    예: "에러 발생", "안 돼요", "X가 작동 안 함", "버그", "크래시"
    권장: "/odebug — 6단계 진단 절차(재현→최소화→가설→측정→수정→회귀) 권장"

  oimprove (코드베이스 부채):
    조건: 기존 코드베이스 정리/리팩토링/부채 청소 요청
    예: "코드 정리", "리팩토링", "부채 갚기", "모듈 단순화"
    권장: "/oimprove — 코드베이스 부채 분석 + 우선순위 추출 후 ok 파이프라인 위임 권장"

  oopus (복잡 위임):
    조건: 복잡한 설계/디버깅/리팩토링 분석, 다중 파일/계층 추적, 트레이드오프 결정
    예: "이 아키텍처 평가해줘", "근본 원인 깊이 분석해줘"
    권장: "/oopus — 복잡한 분석/설계는 Opus 위임 권장"

  ok 파이프라인 (코드 수정):
    조건: 실제 코드 수정/추가/리팩토링/구현 작업
    예: "이 함수 수정해줘", "새 기능 추가해줘", "리팩토링해줘"
    권장: "/ok — 코드 수정은 ok 파이프라인이 안전 (계획→구현→테스트→마무리)"
    세부 tier 권장 (옵션):
      - 1~3 파일, 20~50줄 → /o2
      - 4파일+ 또는 50~500줄 → /o3
      - 500줄+ 또는 아키텍처 변경 → /o4
      - 1500줄+ 또는 전면 변경 → /o5

스킵_조건:
  - 사용자가 이미 슬래시 명령(/ok, /o1~o5, /oopus 등) 명시 호출 → 권장 분기 출력 X
  - 사용자가 이미 결정한 경우 ointaug가 다시 권하지 않음

우선순위_가이드 (위에서 아래로 — 동시 매칭 시 위가 우선):
  1. 단순질문 (직접 답변)
  2. ohaiku (빠른 위임)
  3. osonnet (일반 위임)
  4. odebug (디버깅 우선 — 버그는 즉시 진단)
  5. oimprove (코드베이스 정리 — 분석 후 위임)
  6. oopus (복잡 위임)
  7. ok 파이프라인 (코드 수정)
  원칙: 디버깅은 즉시 진단으로 들어가고, 부채 청소는 분석 후 위임. 둘 다 ok 파이프라인 진입 전에 권장된다.
```

    ⚠️ 의도 불명확: /oss는 스크린샷 스킬인데 "기능 추가"는 코드 수정 의도로 보임 → 1회 확인
  이후:
    → 메인이 AskUserQuestion으로 의도 확인 1회 수행

## 예시

```
원문: "oi 줄여"

확장 질의:
oi/SKILL.md 파일(현재 153줄)을 핵심 로직을 보존하면서 압축하라.
- 대상: <프로젝트 루트>/.claude/skills/oi/SKILL.md
- 보존 필수: spawn 프롬프트(oi-qa/oi-fix-1), 케이스 A/B/C 분기 로직
- 제거 가능: 중복 설명, Step 0 bash 블록(텍스트로 대체), Step 2 TEST/DONE 처리(hook에서 처리)
- 목표: 130줄 이하, oio MCP file_edit으로 수정
- 제약: 실행 신뢰성 유지 (spawn 실패 리스크 없어야 함)

💡 권장 분기: /ok (or /o2) — 코드 수정 작업은 파이프라인 권장 (1~3 파일 추정 → o2)
```

## 주의사항

- ointaug는 **질의를 확장**하는 역할이 주목적. 옵션 C 정책에 따라 조건 충족 시 파이프라인 자율진입도 수행.
- 자율진입 전 반드시 🤖 [자율진입] 통지 1줄 출력 — 생략 금지.
- 자율실행 판정에 1%라도 의심이 있으면 차단(X 조건 적용) — fail-safe 원칙.
- 슬래시 명령(/ok, /o1~o5, /oralph 등)을 포함한 모든 IDLE 상태 입력에 ointaug가 발동된다.
- 이전 대화 참조 시 session_env/plans/user_prompt.md 파일 읽기 활용.

## 슬래시 명령 후 필수 행동 (절대 규칙)

> 슬래시 명령(`/ok`, `/o1`~`/o5`, `/oralph` 등)에서 ointaug가 발동된 경우:

```yaml
금지:
  - 확장 출력 후 Explore/Agent/서브에이전트 spawn 절대 금지
  - 코드 탐색(Glob, Grep, oio bash_exec, Serena) 직접 실행 금지
  - "맥락 파악을 위해 먼저 탐색하겠습니다" 류 행동 금지

필수:
  - 확장 질의 출력 완료 즉시 → 해당 슬래시 스킬 호출
  - /ok     → Skill('ok')
  - /o1     → Skill('ok') (o1 경로)
  - /o2~o5  → Skill('ok') (forced_tier 전달)
  - /oralph → Skill('oralph')  ← oralph가 내부에서 ok → 내장 검증 루프 순서로 실행 (v4.0 — ralph-loop 의존 제거)

호출 순서:
  슬래시_명령:
    일반 명령: ointaug → 직접 답변/실행
    파이프라인: ointaug → Skill('ok')
    복합 스킬: ointaug → Skill('oralph') → [내부: ok → oralph 내장 검증 루프]

  IDLE_일반요청 (비슬래시 입력 — 옵션 C 적용):
    자율실행_가능 (C1·C2·C3 충족): ointaug 확장 출력 → 🤖 [자율진입] 통지 → Skill('ok') 즉시 호출
    자율실행_차단 (X1~X4 해당): ointaug 확장 출력 → AskUserQuestion 1회 확인 → 사용자 결정 대기
    단순질문/분석: ointaug 확장 출력 → 메인 직접 처리 또는 위임 스킬 권장 표시

이유: ointaug는 질의 확장이 주목적. 탐색/실행은 각 스킬의 역할.
      ointaug 이후 직접 탐색 시 ok 파이프라인이 차단되어 17분+ hang 발생 가능.
      자율실행은 반드시 통지 후 진입 — 통지 없는 묵시적 자율진입 금지.
```
