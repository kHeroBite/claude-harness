# oplan_research — 조건부 on-demand 사전 조사 스킬

> **실행 주체**: oplan 팀에이전트 (oplan Phase_A 진입 전 자동 트리거)
> **실행 시점**: oplan tier 확정 후, 파생스킬(oplan_simple/normal/deep) 진입 전 트리거 조건 감지 시 실행
> **목적**: 신규/대규모 작업의 기술 스택, 아키텍처, 외부 의존성을 사전 조사하여 oplan 계획 품질 향상

## 트리거 조건 (3가지 — 하나라도 해당 시 자동 실행)

```yaml
트리거_1_신규_프로젝트:
  감지: 프로젝트 코드베이스가 존재하지 않거나 초기 설정 단계
  예: "새 프로젝트 시작", "처음으로 {기술스택} 도입", "프로젝트 템플릿 생성"

트리거_2_신기술_도입:
  감지: 현재 코드베이스에 없는 라이브러리/프레임워크/패턴 도입
  예: "LiveCharts2 추가", "SignalR 연동", "Docker 도입", "새 인증 방식 적용"
  판단: git history + import 목록에서 해당 기술 미발견 시

트리거_3_대규모_업데이트:
  감지: 핵심 모듈/아키텍처의 대규모 변경 (o4/o5 분류 + 영향 파일 7개+)
  예: "인증 모듈 전면 교체", "DB 스키마 대규모 마이그레이션", "MVC→MVVM 전환"
  판단: oplan이 o4/o5 분류 판정 + 파일 7개 이상 + 아키텍처 변경 감지

트리거_4_사용자_명시_요청:
  감지: 사용자 요청 텍스트에 자료조사 관련 키워드 포함
  키워드: "자료조사", "조사해줘", "리서치", "먼저 조사", "사전 조사", "기술 조사"
  판단: 키워드 매칭 시 무조건 발동 (tier 무관)

비트리거 (스킵):
  - 기존 기능 버그 수정 (단, 원인이 불명확하면 검색 허용)
  - 비코드 파일만 수정 (o1 분류)

외부검색_항상_허용:
  트리거 조건 미해당이라도 계획 수립 중 불확실한 기술 정보가 있으면
  WebSearch/WebFetch로 확인 후 계획에 반영. 추정으로 채우는 것 금지.
```

## 실행 절차

```yaml
Phase_R1_기술_스택_파악:
  1. 현재 코드베이스 기술 스택 확인 (oplan이 이미 수행했으면 결과 재사용)
  2. 도입 예정 기술의 현재 안정 버전 확인 (context7 MCP 또는 공식 문서)
  3. 호환성 매트릭스 작성 (기존 스택 ↔ 신기술)

Phase_R1.5_외부_검색 (WebSearch + WebFetch):
  도구: WebSearch(키워드 검색) → WebFetch(상세 페이지 열람)
  용도:
    - 최신 버전/Breaking Changes 확인 (context7에 없는 경우)
    - Stack Overflow/GitHub Issues에서 알려진 이슈 검색
    - 공식 마이그레이션 가이드/릴리즈 노트 확인
    - 유사 구현 사례/베스트 프랙티스 수집
  우선순위: context7 먼저 → 부족하면 WebSearch 보완
  제한: 검색 5회 이내, 페이지 열람 3회 이내 (비용 절제)

Phase_R2_아키텍처_조사:
  1. 유사 구현 패턴 검색 (프로젝트 내 + 공개 레퍼런스 + WebSearch)
  2. 알려진 위험/주의사항 목록화
  3. 권장 접근법 vs 대안 접근법 비교

Phase_R3_의존성_분석:
  1. 직접 의존성 확인 (패키지, 버전)
  2. 간접 의존성 충돌 여부 확인
  3. 라이선스 호환성 확인 (필요 시)

Phase_R4_조사_요약:
  출력 형식:
    ## oresearch 조사 결과
    - 기술 스택: {확인된 버전 + 호환성}
    - 권장 접근법: {1~3줄}
    - 주요 위험: {항목별 목록}
    - 참조 자료: {URL 또는 문서명}
```

## 실행 모드

```yaml
서브스킬_모드 (기본): oplan 내부에서 Skill('oplan_research') 호출
  - oplan Phase_A 진입 전 트리거 감지 시 자동 실행
  - 조사 결과를 oplan 컨텍스트에 직접 반영
  - 별도 에이전트 spawn 없음 (oplan이 직접 수행)

독립_에이전트_모드 (선택): 메인이 팀에이전트로 spawn
  - 대규모 조사가 필요한 경우 (컨텍스트 분리 효과)
  - spawn 방법: Agent(team_name="{팀명}", name="oresearch-1", mode="bypassPermissions")
  - 결과 반환: SendMessage로 oplan에 조사 결과 전달
```

## 원칙

```yaml
범위_제한:
  - 조사만 수행. 파일 수정 금지.
  - oplan이 조사 결과를 반영하여 계획 수립

시간_제한:
  - 조사 시간 과도 투자 금지 (목적: oplan 품질 향상 보조)
  - 필요 최소 정보만 수집

폴백:
  - 조사 정보 미수집 시 → oplan이 기존 방식으로 계획 수립
  - oresearch 실패가 파이프라인 중단 사유 아님

비트리거_스킵:
  - 트리거 조건 미해당 시 oresearch 호출 금지
  - 불필요한 조사로 파이프라인 지연 방지
```

## 금지 사항

```yaml
금지:
  - 파일 수정 (조사 전용 스킬)
  - 트리거 조건 미해당 시 실행
  - 조사 결과 직접 구현 (odev 역할)
  - 실패 시 파이프라인 중단 (경고 + 계속)
```
